# BC-08 Platform Administration - status

Complete (code + tests + migration). Dev port 5108. DB schema `admin`.

## Implemented
- **Domain**: `PlatformEntityRecord` (US-3.1.4-02 generic admin-created entity record, typed by `PlatformEntityType`),
  `JobOffering` (moderation target - suspend/remove, `RegisterJobOfferingHandler` creates one per BC-09 `JobPostingCreated`),
  `ReferenceFile` (`ReferenceEntry` child list, versioned, in-use guard before removing an entry), `SystemSetting`
  (`SystemSettingChange` history entries, versioned), `PlatformTaxonomy` (`TaxonomyNode`/`TaxonomySnapshot`, versioned,
  publishes the changed-codes diff). All five aggregate roots are sealed; error codes `E-AUM-FORBIDDEN` /
  `E-AUM-*` and rule codes under `Common/Common.cs`.
- **Application**: full command/query set for `EntityRecords`, `Offerings` (suspend/remove job offerings), `Reference`
  (`ReferenceFileReader` + update-with-in-use-confirmation), `Settings` (change + history), `Taxonomy`
  (`TaxonomyReader` + update-with-changed-codes), `Users` (composed read of BC-03 via `IUserDirectory`).
  `PlatformAdministrationEventMapper` publishes the 5 integration events below. One inbox handler,
  `RegisterJobOfferingHandler`, consumes BC-09's `JobPostingCreated`. `ILaterSaveWinsCommand` marker interface opts
  settings/reference-file/taxonomy commands into retry-on-conflict semantics (see Infrastructure). Dual-provider ports
  `IUserDirectory` (BC-03) and `IReferenceUsageChecker` (checked before removing a reference entry), each `Http | Fake`.
- **Infrastructure**: EF Core `AdminDbContext` (schema `admin`), repositories for every aggregate, `AdminReadStore`,
  `AdminSeeder` (`IDbSeeder<AdminDbContext>`, seeds reference/taxonomy defaults on startup), `ReferenceDataCache`,
  `LaterSaveWinsBehavior<TRequest,TResponse>` - a pipeline behavior inserted **in front of** the unit-of-work behavior that
  repeats a `ILaterSaveWinsCommand` up to 5 times on an optimistic-concurrency conflict (`E-CONCURRENCY-CONFLICT`), clearing
  the change tracker and draining buffered domain events between attempts so "the last request to run wins" (US-3.1.4-06/07/08
  AC-03) instead of rejecting the loser outright. Outbox/inbox wiring, initial migration.
- **Api**: `AdminControllerBase` (Administrator role + MFA, `E-AUM-FORBIDDEN`) with `UsersController`
  (`/api/v1/admin/users`), `EntityRecordsController` (`/api/v1/admin/entity-records`), `SettingsController`
  (`/api/v1/admin/settings`), `ReferenceFilesController` (`/api/v1/admin/reference-files/{type}`),
  `TaxonomiesController` (`/api/v1/admin/taxonomies/{type}`, ETag = version), `JobOfferingsController`
  (`/api/v1/admin/job-offerings`, list/suspend/remove). `InternalController` (`/internal/v1/taxonomies/{type}`,
  `/internal/v1/reference-files/{type}`, `/internal/v1/settings/{key}`, client-credentials service token) implements the
  shared `TaxonomyDto`/`TaxonomyEntryDto` contract consumed by other BCs (BC-04, BC-09, BC-11, ...), including an
  If-None-Match-style `?version=` request returning `404` for an unknown version rather than the latest.

## Assumptions / deviations
- **"Later save wins" instead of reject-on-conflict**: settings/reference-files/taxonomies deliberately retry the loser of a
  concurrent save (up to 5 attempts) rather than surfacing `409` to the client, per AC-03 of their respective stories; every
  attempt still appends its own version/history row so no intermediate edit is silently lost from the audit trail, only the
  final state is "last write wins".
- **User management is a read-only composition of BC-03**: `ListPlatformUsersQuery` never writes to BC-03's own account data;
  `IUserDirectory` is a dual `Http | Fake` provider exactly like the other cross-BC read ports elsewhere in the platform.
