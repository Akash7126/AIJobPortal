# BC-07 Audit Logging - status

Complete (code + tests + migration). Dev port 5107. DB `JobPlatform_AuditLogging`, schema `audit`.

## Implemented
- Domain: `AuditEntry` (append-only, INV-01/02/03), `OwnerScope`, `DetailsPolicy` (no PII), `AccessScopePolicy`, `RetentionPolicy`, `CandidateInsightPolicy`,
  `SyncJobStatus` state machine, `IntegrationUsageDaily`/`UsageWindow`, `JobStatusHistoryEntry`, `NotificationLogEntry`, `EmployerDashboard`, `CandidateInsightRecord`, `ExportJob` (INV-04).
- Application: 21 inbox handlers (19 catalogued events + `JobPostingCreated` for the dashboard + generic `AuditRecord` stream), 17 queries, 1 export command + runner, archive command, validators.
- Infrastructure: EF context (`audit` schema), repositories, read store, `SimulatedReportGenerator` (BC-12 port), retention + export background services, initial migration.
- Api: 17 endpoints of handover 6.1 (`/api/v1/partners/me/*`, `/admin/audit/*`, `/admin/reports/exports`, `/employers/me/*`, `/jobs/{id}/status-history`, `/users/me/notifications/history`).

## Assumptions / deviations
- Uniqueness of INV-01 is `(SourceBc, SourceMessageId, Category)` because one event feeds several logs (submission log + job audit trail).
- E-mail and SMS logs share one `NotificationLog` table (channel column) instead of two tables.
- `JobPostingCreated` is consumed too (handover Q-05) so the employer dashboard can list postings. `JobPostingUpdated/StatusUpdated` and `CandidateInsightComputed` contracts carry `EmployerAccountId` (and insight fields) additively.
- Matched/viewed usage counters stay 0 (no source events, Q-02). Monthly SQL Server partitioning is not implemented; entries are flagged `IsArchived` (kept, never purged).
- Redis caching of dashboards is not implemented (always read fresh). Report generation uses a simulated adapter until BC-12's API is wired.
- Localisation uses an in-code catalogue (`AuditErrorMessages`), test-enforced en+ar.
