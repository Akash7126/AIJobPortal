## Implemented
- **Domain**: `MatchScore`, `CandidateShortlist`, `JobRecommendation`, `JobSemantics`, `MatchingConfiguration` (+ `ConfigurationHistoryEntry`), `ParsedProfileData` (+ `ProfileField`), `ResumeParsedData` (+ `ParsedField`), `SkillStandardization` (+ `SkillMapping`) aggregates; `KnownProfile`/`KnownPosting`/`MatchingWorkItem` read-side replicas of other BCs' data.
- **Application**: `MatchComputationService` (scoring engine), `Semantics.cs`/`Parsing.cs` (job/resume text processing), `Recommendations.cs`/`Shortlists.cs` (query + command handlers), `WorkRunner.cs` (background matching work queue), `EventMapper.cs` (domain -> integration events), `InboxHandlers.cs` (consumes upstream BC events to keep `KnownProfile`/`KnownPosting` replicas current).
- **Infrastructure**: EF Core `AiMatchingDbContext` with PII-aware mappings (`Pii.cs`), a hashing-based `HashingEmbeddingService` and rule-based `RuleBasedResumeParser`/`TextExtraction` (no real ML/LLM embedding or resume-parsing model wired here - deterministic stand-ins), `ConfigurationProvider`/`SkillTaxonomyProvider`/`Directories` adapters, `BackgroundServices.cs` for async match computation, `ApiClients.cs` for calling other BCs.
- **Api**: `GET /matches/jobs`, `GET /matches/jobs/{jobPostingId}`, `GET /recommendations/jobs`, `GET /candidates`, `GET /candidate-recommendations`, `POST /shortlists`, `GET /shortlists/{id}`, configuration read/update (`GET`/`PUT /{field}`, `PUT /threshold`, `PUT /weights`), `GET /match-ranking`, `GET /match-scores`, `GET /resume-parsed-data/{id}` - all routes present and smoke-tested by `Api.IntegrationTests`.

## Known limitations
- The embedding/semantic-matching layer is a deterministic hashing stand-in, not a real ML model - matching quality has not been validated against real job/resume text at any scale, only unit-tested for the plumbing (scoring math, threshold/weight application, shortlist assembly).
- No Docker/SQL Server/RabbitMQ/Redis available in this environment - Infrastructure tests run against SQLite/in-memory equivalents only, so the real-database and real-broker paths are unverified here.
- This BC's own narrative write-up (this file) was produced after the fact from the existing code and test suite, not by the agent that originally wrote the production code - treat the "Implemented" section above as a read of what exists rather than a first-hand account of the implementation decisions behind it.
